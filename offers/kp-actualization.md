# Актуализация КП под клиента

**Зачем:** один канон офферов → разные тексты и сборки без ломки цены.  
**Главный вход:** `LOC-PILOT` · `offers/LOC-PILOT-canon.md`  
**Карта офферов:** `offers/offers-model.md`

---

## 1. Входы (из M1 / созвона)

| Поле | Откуда | Зачем |
|---|---|---|
| `trigger` | T1–T6 | Модули и ступень по умолчанию |
| `niche` | девелопмент / модуль / ремонт / иное | Язык, KPI, каналы |
| `track` | A / B | LOC-PILOT vs FIX |
| `goal_one` | ЛПР своими словами | Заголовок КП |
| `budget_signal` | есть / нет / вилка | Smoke vs Standard vs Serious |
| `assets` | сайт, CRM, ОП, кабинеты | Что реально входит |
| `constraints` | закупки, брендбук, сезон | Вариант A/B оплаты, срок |
| `next_hypothesis` | OX / K1 / B | Блок decision |

Без `goal_one` и `trigger` КП не собираем — только nurture.

---

## 2. Алгоритм сборки (10 минут)

```
1. Выбрать код оффера (почти всегда LOC-PILOT на A)
2. Взять default_tier + modules из триггера (loc-pilot-calc.json)
3. Поджать/расширить модули по assets (нет ОП → слабее COM-ENABLE; нет сайта → IT-LAND обязателен)
4. Выбрать envelope в коридоре ступени (не ниже min Impro 250к)
5. Заполнить шаблон КП человеческой целью (не «пакет T2»)
6. KPI: 2–4 ориентира в языке ниши
7. Decision: один явный next
8. Скопировать блок из калькулятора / вставить цифры
```

---

## 3. Язык ниши (подстановки)

| Ниша | «Лид» звучит как | Типовой KPI |
|---|---|---|
| Модульные дома | заявка / выезд замерщика | CPL, % до замера, авансы |
| Ремонт | заявка на смету | CPL, скорость ответа, % до сметы |
| Застройщик | лид в CRM / визит / бронь | CPL, визиты, стоимость брони |
| Иное mid | квалифицированный лид | CPL, % квалификации, ROMI пилота |

В КП не пишем внутренние коды модулей без расшифровки.

---

## 4. Что можно менять / что нельзя

| Можно | Нельзя без ревизии канона |
|---|---|
| Ступень в коридоре | Impro << 30% «чтобы зайти» |
| Состав 1–3 модулей | Пилот без аналитики и креатива |
| Вариант A (всё в конверте) vs B (media отдельно) | Гарантия N договоров штрафом |
| Срок 30/60/90 | «Аудит/план» вместо исполнения |
| Оплата 50/50 vs 40/30/30 | Убрать decision meeting |
| Зачёт 100% → 50% только осознанно | Назвать FIX «партнёрством» |

## 5. Примеры быстрой актуализации

### A. Модуль, T2, Standard
- Конверт 2.0м · Impro 700к  
- Модули: PERF + IT-LAND (квиз) + COM-ENABLE  
- Цель: «снизить стоимость договора и поднять долю заявок до замера»  

### B. Ремонт, T5, Smoke
- Конверт 0.8м · Impro 280к  
- Модули: PERF (Авито/Директ) + COM-ENABLE light  
- Цель: «проверить связку трафик → смета за 30 дней»  

### C. Застройщик, T3, Serious
- Конверт 5.0м · Impro 1.75м  
- Модули: креатив + PERF + CLASS + IT-LAND + COM-ENABLE  
- Цель: «первая волна спроса на корпус / очередь»  

### D. Просит «только Директ за 40к»
- Не LOC-PILOT. FIX-P02 или отказ / nurture.  
- Если mid и боль системная — мягко вернуть к Smoke.

## 6. Чеклист перед отправкой КП

- [ ] Одна цель глазами клиента  
- [ ] Ступень и цифры из канона / коридора  
- [ ] Модули стыкуются с триггером и assets  
- [ ] «Не входит» проговорено  
- [ ] KPI без штрафной гарантии  
- [ ] Decision и зачёт указаны  
- [ ] Нет микросметы «по часам каждого действия» в клиентском КП
